# Комплект подготовки настоящего набора A/B/C

**Статус: здесь нет аудио и проверенных эталонов.** Это законченные инструкции,
плановые сценарии, пустой TSV и шаблон метаданных. Не включать их в manifest
эксперимента как готовые записи. Не копировать сценарии в reference.

Нужны два согласившихся участника, Android с локальным диктофоном и компьютер
с установленными `requirements-evaluation.txt`. Для разметки — локальный
Audacity/ELAN либо другой редактор с волной и точным временем. Третий человек
необязателен. Код приложения и issue #5 менять не требуется.

## Роли и результат

1. **Участник P1:** организует согласия, записывает три диалога вместе с P2,
   делает первичную расшифровку и TSV-разметку по аудио, заполняет метаданные.
2. **Участник P2:** независимо слушает каждый файл, проверяет **все** слова,
   постоянство спикеров, начала/концы и наложения. Спорные участки слушают вместе;
   в notes сохраняют, что исправлено и где осталась неопределённость.

Результат каждого сценария — неизменённый оригинал, рабочий `audio.wav`,
`annotations.tsv`, строгий `reference.json`, `metadata.json`, документ о правах.
Для A/B/C использовать разные каталоги. Участник может размечать один, но
обязан оставить reviewers пустым и зафиксировать ограничение: валидатор
предупредит, что независимой проверки нет. `verified` — ручное утверждение,
не автоматическое доказательство правильности текста.

## 1. Права и приватность — до записи

- Согласовать с каждым участником цель: локальное тестирование ASR/диаризации,
  состав команды с доступом, сроки/место хранения, порядок отзыва согласия.
- Отдельно зафиксировать разрешение на запись, хранение/обработку и публикацию
  аудио **и разметки**. Разрешение обработки не разрешает публичный GitHub.
- Зафиксировать правообладателей, дату и действительные условия/лицензию,
  подтверждение всех участников. Если публикация запрещена, указать
  `publication_allowed: false`, хранить всё вне публичного репозитория.
- Реальный документ/подтверждение сохранить как `rights.txt` либо указать
  другое локальное имя в source.rights_file. В Git не помещать подписи,
  настоящие имена и приватные контакты. В метаданных допустимы псевдонимы.
- Внешний источник требует доказательства лицензии именно на аудио,
  атрибуции, URL и версии. Лицензия ASR-модели или кода не покрывает WAV автоматически.

Шаблон metadata имеет `rights_reviewed: false` и невалидные SHA-256 намеренно.
Менять флаг только после фактической проверки документов человеком. Валидатор
проверяет наличие/хеш документа, **не юридическую действительность согласий**.

## 2. Запись на Android

1. Встроенный или заранее установленный диктофон должен сохранять локальный
   файл. Отключить облачную синхронизацию; включить авиарежим, отдельно отключить
   Wi-Fi. Не пользоваться онлайн-расшифровкой или обработкой голоса.
2. Разрешить микрофон; выбрать WAV/PCM без автоматического шумоподавления,
   если диктофон это поддерживает. Если нет — сохранить исходный M4A/другой
   доступный формат и записать его настройки, не выдавая его за исходный PCM.
3. Записать короткую пробу, локально прослушать обоих участников: нет клиппинга,
   голос различим, уведомления/звонки не мешают. Пробу в основной набор не включать.
4. Записать A, B, C по [scenarios.md](scenarios.md), каждый целым дублем 1–3 минуты.
   Фактическая длительность может отличаться от плана. Не делать монтаж
   синтетического overlap. В C должны одновременно звучать два реальных голоса.
5. Прослушать файл на телефоне; если речь неразборчива, повторить дубль,
   не восстанавливать слова по сценарию. Не редактировать оригинал.
6. Через USB/SAF передать файл на компьютер в закрытый каталог, например
   `$HOME/catscriptor-evaluation-private/A`. Сохранить device/микрофон/формат/
   расстояния/шум/дату и SHA-256 оригинала в source.description или журнале.

Для удобства используйте отдельные A/B/C-каталоги **вне checkout**. Комплект
не включает приватные файлы в .gitignore всего проекта: безопасность должна
обеспечиваться местом хранения, а не надеждой на случайное игнорирование.

Если диктофон не дал PCM 16 кГц mono, локально преобразовать FFmpeg (отдельная
необязательная утилита, не Python-зависимость; сохранить её версию и команду):

```bash
ffmpeg -n -i original.m4a -map 0:a:0 -ac 1 -ar 16000 -c:a pcm_s16le -map_metadata -1 audio.wav
```

Не менять скорость, не обрезать тишину, не нормализовать громкость скрытно.
Разметка и ASR должны относиться к **полученному audio.wav**, а не к иному
нулю времени/файлу. Исходное M4A сохранить отдельно; codec delay может отличаться.

## 3. Ручная разметка без изменения кода

1. Скопировать `turns.template.tsv` в закрытый каталог как `annotations.tsv`,
   `metadata.template.json` как `metadata.json`.
2. Открыть audio.wav локально. Прослушать всё и определить голоса. speaker_1 —
   фактически первый говорящий, speaker_2 — следующий новый голос, не номер хода.
3. В UTF-8 TSV заполнить четыре столбца, разделённые **табуляцией**:
   `speaker_id`, `start_ms`, `end_ms`, `text`. Можно использовать таблицу
   LibreOffice с экспортом Text CSV / Tab / UTF-8, без автоизменения значений.
   Не добавлять индекс, комментарии, дополнительные столбцы и фиктивные строки.
4. Время абсолютное от начала WAV, целые миллисекунды. Если редактор показывает
   часы/минуты/секунды: `ms = h*3600000 + min*60000 + seconds*1000` с округлением
   по реальной границе. Удобнее переключить отображение в миллисекунды.
   Начало — первый речевой звук, конец — последний, не середина паузы.
5. Непрерывный ход спикера — одна реплика, пауза >=500 мс разделяет реплики.
   Это единая политика данного небольшого набора, не встроенная логика scorer.
   Слышимые междометия, повторения, оговорки сохранять; порядок слов не исправлять.
6. Наложения — две отдельные строки с пересекающимися интервалами и разными
   speaker_id. Отсортировать по start_ms; при равенстве — стабильный speaker_id.
   Не использовать интервалы из сценария: там только план, не измерения.
7. Переслушать на нормальной/замедленной скорости, сверить по волне/спектрограмме.
   Не делать ASR единственным источником эталона. Неразборчивые участки не
   угадывать: повторить запись целиком или отложить её вне оцениваемого набора.
8. P2 проверяет исходное аудио и разметку, не полагаясь на память сценария.
   Совместно исправить споры; в notes описать проверку и ограничения точности.
   Пословных меток нет — `word_timestamps: unavailable`; не делить реплики поровну.

Конвертация не сортирует и не исправляет разметку скрытно:

```bash
python -m tools.evaluation.dataset convert --annotations /private-data/A/annotations.tsv --output /private-data/A/reference.json
python -m tools.evaluation.dataset inspect --audio /private-data/A/audio.wav --reference /private-data/A/reference.json --rights /private-data/A/rights.txt
```

Заменить `/private-data` на свой каталог (на Windows допустимы обычные Windows
пути). Конвертер создаёт **только новый** файл; после исправлений экспортировать
в новое имя, сохранить старую версию и обновить reference_file в metadata.
Никогда не переименовывать старый результат ASR в reference.

## 4. Метаданные и проверка

Перенести из `inspect` **фактические** audio, audio_sha256, reference_sha256
и source.rights_sha256. Остальные поля заполнить вручную: ID, scenario,
описание источника/преобразований, правообладатели, реальные условия/лицензия,
проверка прав, разрешение публикации, устройство/условия/дата, псевдонимы
разметчика и проверяющего, инструмент/версия, политика, журнал проверки.
После ручного завершения поставить annotation.status=verified.

```bash
python -m tools.evaluation.dataset validate --metadata /private-data/A/metadata.json
python -m tools.evaluation.dataset validate --metadata /private-data/A/metadata.json --require-verified
```

Повторить для B/C. Валидатор проверяет строгую схему reference, сортировку,
границы относительно точного числа сэмплов, PCM-формат и отсутствие обрыва WAV,
SHA-256, число спикеров, наличие overlap в C, описание прав и ручной проверки.
Draft или единственный разметчик явно отображаются/дают предупреждение;
`--require-verified` отвергает draft. Exit 0 — структурная согласованность,
exit 2 — ошибка. Это **не** автоматическое доказательство, что WAV содержит
диалог, что речь шумная/разборчивая или что текст соответствует звуку.

## 5. Передача разработчику #5 и измерения

Передать разрешённым закрытым способом audio.wav, reference.json, metadata.json
и контрольные суммы. Документы с личными данными держать отдельно с доступом
только согласованных участников. Без согласия на публикацию GitHub не использовать.

На настоящем Android импортировать **тот же WAV** в APK, получить экспорт
Catscriptor. Записать модель/вариант/квантизации всех стадий, устройство,
потоки, commit APK и измеренное монотонным таймером время. Только после этого
создать measurement.json согласно [методике](../../../../docs/evaluation.md).
Если время неизвестно — не указывать его; RTF останется null.

```bash
python -m tools.evaluation.evaluate --reference /private-data/A/reference.json --hypothesis /private-data/A/catscriptor.json --measurement /private-data/A/measurement.json --output /private-data/A/report.json
```

Для трёх записей составить manifest с реальными путями. Перед публикацией
отчётов проверить права на текст — отчёт содержит расшифровку. Заполнить
`docs/TEST_RESULTS.md` только измеренными числами и ссылками на разрешённые
артефакты; не добавлять приватные файлы в Git. Пока экспорта #5/записей нет,
WER/DER/MAE/RTF реального пайплайна остаются **не измерены**.
