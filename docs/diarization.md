## Конвейер

`SAF → Foreground Service → PCM → VAD (закрыт) → диаризация (закрыта) → ASR по ходам спикеров → слияние`

Реализует `DiarizedDraftRunner` — единственный запускатель этапов в сервисе (прежние `AsrDraftRunner` и `PipelineOrchestrator` удалены в #8).
Порядок `ProcessingStage` изменён: `PREPARE_AUDIO, DETECT_SPEECH, DIARIZE, TRANSCRIBE, CORRECT_TEXT`.
Одновременно в памяти одна модель; PCM закрывается после ASR. Результат остаётся статусом
`AsrReady` (черновик): коррекции LLM (#7) нет, экспорт запрещён.

Один проход GigaAM: каждый участок аудио распознаётся один раз, ASR запускается только по ходам.
Текст никогда не делится между спикерами, пословных меток нет.

### Почему этот набор

- Уже есть в sherpa-onnx 2.0.1 (AAR): отдельный ONNX Runtime не нужен, JNI-классы подтверждены `javap`.
- Автоматическое число спикеров: `FastClusteringConfig(numClusters = -1, threshold)`.
- Pyannote 3.0 использует powerset-метки, то есть модель сама отмечает перекрывающуюся речь.
- Reverb v1/v2 (11 МБ / 254 МБ) и модели NeMo/WeSpeaker не выбирались: v2 слишком тяжёлая для APK,
  остальные не проверялись на русской речи. **Утверждений о качестве на русском нет.**

## Архитектура

| Класс | Назначение |
|---|---|
| `SherpaDiarizationBackend` / `SherpaDiarizationResource` | `DiarizationBackend` поверх `OfflineSpeakerDiarization`; ленивые модели, `close()` идемпотентен, после ошибки/отмены backend закрывается |
| `ChunkedDiarizer` | окна ограниченной длины + глобальное сопоставление спикеров; тестируется без нативного кода |
| `DiarizationWindowPlanner` | окна ≤ 8 мин по паузам VAD, запас тишины 0,5 с, жёсткий разрез сегмента длиннее окна |
| `GlobalSpeakerRegistry` | центроиды эмбеддингов, косинусная близость, один глобальный спикер на локального в окне |
| `SpeakerTurnPlanner` | интервалы диаризации → непересекающиеся ходы для ASR |
| `DefaultUtteranceMerger` | назначение спикера по пересечению и склейка реплик |

### Длинные записи

`OfflineSpeakerDiarization.process(FloatArray)` принимает весь массив, а кластеризация строит матрицу
попарных расстояний по парам «окно сегментации × спикер» (O(N²), исходник `fast-clustering.cc` v2.0.1).
Поэтому запись режется на окна ≤ 480 с (≤ 30,7 МБ `FloatArray`), PCM читается блоками по 8192 отсчёта.
Колбэк прогресса sherpa **не умеет прерывать** нативный вызов, поэтому отмена проверяется между окнами и
после возврата из JNI (в пределах одного окна отмена ждёт окончания его обработки).

Каждое окно кластеризуется независимо, метки между окнами не связаны. Для многооконной записи для каждого
локального спикера считается эмбеддинг по его речи **без пересечений с другими**, до 15 с; реестр
сопоставляет их с глобальными по косинусу (порог `1 − clusteringThreshold`). Короткая речь (< 1 с) не
создаёт нового спикера; меньше 0,4 с чистой речи — интервалы спикера отбрасываются, а не назначаются наугад.
Итоговые `speaker_N` нумеруются по порядку появления; разрывы ≤ 0,2 с одного спикера на стыках склеиваются.
**Многооконный режим проверен только заглушками моделей** (тест инвертированных меток), на реальных данных нет.
Записи ≤ 8 мин речи обрабатываются одним окном без своей логики сопоставления.

### Постобработка и ходы (`SpeakerTurnPlanner`)

1. Интервалы обрезаются по речи VAD (± 150 мс): тишина не получает спикера.
2. Развёртка по времени. При перекрытии участок остаётся за спикером, который говорил непосредственно
   перед ним; при одновременном начале — за начавшим раньше, затем меньший номер.
3. Склейка пауз одного спикера ≤ 400 мс; ходы < 300 мс не отправляются в ASR.

Один VAD-сегмент с двумя спикерами превращается в два ASR-вызова по ходам (тест
`modelsAreLoadedOneAtATimeAndClosedBeforeTheNextStage`).

### Слияние (`DefaultUtteranceMerger`)

- Спикер ASR-фрагмента: наибольшее суммарное пересечение (объединение интервалов спикера); при равенстве
  большее IoU, затем более раннее начало пересечения, затем меньший номер. Нет пересечения → `SpeakerAssignmentException`,
  `speaker_1` не подставляется. Пустой ASR реплик не создаёт.
- Склейка соседних реплик одного спикера: пауза ≤ 1 с, нет реплик других спикеров между ними, в паузе нет
  речи другого спикера ≥ 200 мс, результат ≤ 60 с. Текст не теряется и не дублируется (тест).
- Merger получает **ходы** как `SpeakerSegment`: время ASR-фрагмента совпадает с интервалом хода, поэтому
  длинный чужой ход не перетягивает назначение.

## Ограничения

- **Перебивания.** Без разделения источников одновременная речь не разделяется. Участок перекрытия
  распознаётся один раз и достаётся говорившему первым; реплика перебившего *внутри* чужого хода остаётся
  в тексте владельца хода, а собственной репликой становится лишь непересекающаяся часть. Дублирования текста нет,
  но и «двух независимых реплик» из одного звука тоже нет. Реальное качество на перебиваниях не измерено.
- Pyannote 3.0 различает не более трёх спикеров в одном 10-секундном окне; влияние на запись не измерено.
- Порог кластеризации не валидирован на русской речи (см. выше).
- ASR по ходам: ходы < 300 мс отбрасываются, ход > 25 с режется на технические порции GigaAM.
- LLM-коррекция (#7) добавляется этапом в `DiarizedDraftRunner`; модель загружается после закрытия GigaAM.
- Хранилище результатов — в памяти процесса.
