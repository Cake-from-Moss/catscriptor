# Запись микрофона (#21)

Основная сборка записывает микрофон через Android `MediaRecorder`: AAC, M4A,
моно, 44,1 кГц, 128 кбит/с. Разрешение `RECORD_AUDIO` запрашивает существующий
экран; без разрешения или доступного микрофона запись не начинается.

1. Откройте главный экран и разрешите доступ к микрофону.
2. Начните запись. Пауза исключается из таймера; отметки используют время
   записанного аудио, а не время, проведённое на паузе.
3. Нажмите «Стоп»: контейнер завершается, файл передаётся в существующую очередь
   через `ProcessingController.importFile()`. Идентификатор возвращает очередь.

Файлы находятся в приватном `filesDir/recordings/`, а не во временном кеше.
`FileProvider` открывает только этот каталог и выдаёт локальный `content://` URI:
его может читать существующий `AndroidAudioDecoder` в процессе приложения,
включая сервис обработки. Разрешения на общее хранилище не нужны.

## Ограничения первой версии

- Оставайтесь в приложении во время записи. Отдельного microphone foreground
  service нет; запись при сворачивании, блокировке экрана и смерти процесса
  не гарантируется.
- Live-ASR не запускается, `liveLines` пуст. Переключатель Live-текста не меняет
  записываемое аудио; обработка начинается после остановки.
- Индикатор показывает пик `MediaRecorder.maxAmplitude` за интервал опроса,
  преобразованный в dBFS, не RMS. VAD во время записи не выполняется.
- Слишком короткая запись может не сформировать корректный M4A: такой файл
  не передаётся на обработку. Ошибки затрагивают только текущую сессию.
- Перед началом и во время записи проверяется резерв свободного места 5 МиБ.
  При его исчерпании контроллер пытается завершить контейнер и освобождает
  микрофон. Завершённые файлы сохраняются и при отказе очереди; автоматического
  восстановления/повторного импорта таких файлов пока нет.
- Системная блокировка микрофона может давать тишину вместо ошибки Android.
  Нулевая амплитуда не выдаётся за результат Silero VAD.

## Проверка

JVM-тесты: `RecordingControllerTest`, `HomeViewModelTest`.
Android-тесты записи находятся в пакете `org.cfm.catscriptor.recording`;
для проверки микрофона нужен доступный Android-телефон с выданным разрешением.
Бинарные пользовательские записи в репозиторий не добавляются.

Общая проверка сборки и JVM-тестов:

```bash
./gradlew assembleDebug assembleRelease test :app:assembleDebugAndroidTest
```

После установки debug APK и test APK:

```bash
adb shell am instrument -w -r \
  -e class org.cfm.catscriptor.recording.RecordingFileProviderTest \
  -e recordMicrophone true \
  org.cfm.catscriptor.test/androidx.test.runner.AndroidJUnitRunner
```

Аргумент `recordMicrophone=true` явно разрешает тесту использовать микрофон;
без него микрофонная проверка пропускается. Тест выдаёт разрешение через shell,
открывает Activity, записывает с паузой и декодирует M4A. Отдельная интеграционная
проверка заменяет только источник аудио готовым тестовым M4A, но использует
настоящие `stop → importFile → AudioProcessingService → AndroidAudioDecoder`
и проверяет успешное завершение подготовки аудио.

Проверено 07.11.2026:

- `assembleDebug assembleRelease test :app:assembleDebugAndroidTest --offline` —
  успешно; JVM: 132 теста, из них 1 пропущен, ошибок нет.
- vivo V2538, Android 16 / API 36, arm64-v8a: все 3 Android-теста прошли
  с `recordMicrophone=true`, включая настоящую запись с паузой и возобновлением,
  чтение через FileProvider и передачу файла сервису обработки.
- Фоновая запись и восстановление после смерти процесса не проверялись
  и не входят в гарантии этой версии.
